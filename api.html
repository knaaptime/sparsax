    API reference¶

    The public API is split across two modules: the JAX frontend in sparsax and the optional PyTensor frontend in sparsax.pytensor.

    JAX frontend (sparsax)¶

    Sparse Cholesky (CHOLMOD) solvers for symmetric positive definite matrices, exposed as XLA FFI custom calls that run at full native speed inside @jax.jit (and lax.scan / lax.fori_loop). Symbolic analysis is cached on the sparsity pattern, so repeated solves with the same pattern only pay for the numeric refactorization.

    solve

    Solve A x = b for symmetric positive definite sparse A.

    logdet

    Log-determinant of a symmetric positive definite sparse matrix.

    selinv

    Selected inverse: entries of A^{-1} at A's sparsity pattern.

    factor_solve

    Factor A once, then run several solve chains from that one factor.

    sample_gaussian

    Draw eta ~ N(A^{-1} b, A^{-1}) from a single factorization of A.

    update_solve

    Solve (A ± C C') x = b via a rank-k update of A's factor.

    solve_bcoo

    solve() for a JAX BCOO matrix A.

    logdet_bcoo

    logdet() for a JAX BCOO matrix A.

    update_solve_bcoo

    update_solve() for a JAX BCOO base matrix A.

    set_options

    Configure CHOLMOD behavior.

    clear_cache

    Free all cached symbolic analyses and factorizations.

    cache_size

    Number of sparsity patterns currently cached.

    factorization_count

    Total numeric (re)factorizations performed since import.

    Sparse LU (KLU)¶

    Sparse LU solver for general (non-symmetric) matrices, e.g. A = I - rho W for a row-standardised spatial weights matrix.

    lu_solve

    Solve A x = b for a general (non-symmetric) sparse A via KLU.

    lu_solve_bcoo

    lu_solve() for a JAX BCOO matrix A.

    set_lu_cache_size

    Set how many KLU numeric factors are retained per sparsity pattern.

    Solve modes¶

    Constants selecting which system is solved by solve() and update_solve(). The factorization is P'LL'P = A, so e.g. sampling from N(0, A^{-1}) is solve(..., z, mode=MODE_LT) followed by solve(..., ., mode=MODE_PT).

    MODE_A

    int([x]) -> integer int(x, base=10) -> integer

    MODE_LDLT

    int([x]) -> integer int(x, base=10) -> integer

    MODE_LD

    int([x]) -> integer int(x, base=10) -> integer

    MODE_DLT

    int([x]) -> integer int(x, base=10) -> integer

    MODE_L

    int([x]) -> integer int(x, base=10) -> integer

    MODE_LT

    int([x]) -> integer int(x, base=10) -> integer

    MODE_D

    int([x]) -> integer int(x, base=10) -> integer

    int([x]) -> integer int(x, base=10) -> integer

    PyTensor frontend (sparsax.pytensor)¶

    A second frontend over the same cached CHOLMOD core, for use with PyMC’s default (PyTensor) backend — including gradient-based samplers like NUTS. These are pure-Python Ops whose perform calls the numpy-callable core; they do not go through JAX/XLA. Install with pip install sparsax[pytensor].

    solve

    Solve A x = b for SPD sparse A (PyTensor).

    logdet

    log|A| (PyTensor), differentiable in Ax.

    selinv

    Selected inverse A^-1 at the pattern (PyTensor).

    PyTensor Ops¶

    The Op classes backing the convenience functions above. Documented for users who need to construct or introspect them directly.

    class sparsax.pytensor.CholmodSolve(mode=0)[source]

    Solve A x = b (or a factor-part system) from cached CHOLMOD factor.

    Differentiable in Ax and b only for mode == MODE_A; other modes are forward-only (their VJP is undefined, matching the JAX solve).

    class sparsax.pytensor.CholmodLogdet(n)[source]

    log|A|. Differentiable in Ax via the selected inverse.

    class sparsax.pytensor.CholmodSelinv(n)[source]

    Selected inverse: A^-1 at A’s pattern. Forward-only.
